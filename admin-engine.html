What the developer connects

Replace the simulation with the API

  1. HBX.world() builds rows here; in production the test engine already writes them to student_question_analytics.
  2. HBA.sim.aggregate() mirrors the existing aggregation job that fills the *_v2 indexes.
  3. HBA.buildStudentReport() is the part that ships unchanged: give it a student's rows plus the test benchmarks.
  4. The report service (hitbullseye-reports) already calls the API and embeds into the student dashboard with a signed token.

Fields the test engine must record

Already in the raw index. The ones the insights depend on most:

  • timeTaken per question: pacing, rushed answers, time sinks, stamina
  • isAttempted, isCorrect, score: accuracy, penalties, potential score
  • areaId, subAreaId, lod: topic map, weak sub-topics, difficulty
  • firstViewedAt: question order for stamina and pacing
  • selectedAnswer: distractor analysis in Insights
